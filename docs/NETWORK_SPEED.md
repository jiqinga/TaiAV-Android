## 实际数据

当前测试媒体列表域名为 `taiav.com`，视频分片来自 `v11cdn.snmovie.com`。系统 DNS、Google DNS 与 Cloudflare DNS 均返回 IPv4 `91.211.251.152`。因此这次查询没有展示仅换这几种 DNS 即切换到其他视频节点的收益。

电脑上对同一 HTTPS 分片取前 256 KiB，保留 Referer / User-Agent、TLS 验证和签名查询，仅输出计时与域名，不保存媒体内容：

| 路径 | HTTP | 响应头等待 | 总用时 | 含连接等待的平均速度 |
|---|---|---|---|---|
| 电脑直连 | 206 | 2.09 秒 | 5.72 秒 | 44.8 KiB/s |
| 电脑现有代理 | 206 | 1.30 秒 | 2.89 秒 | 88.6 KiB/s |

这是小样本电脑对比，包含连接与 TLS 时间；尚未在手机上对同一代理复核，也不等同于稳定下载速率。结果支持继续比较视频 CDN 的出口线路，尚不足以判定源站固定限速或代理持续提速比例。

真机同一离线任务先后两个约 25 秒窗口，以应用私有下载目录增加的字节数估计：3 路时 14.0 KiB/s，更新并续传后的 6 路时 125.2 KiB/s。两段测量不在同一时刻，网络、分片大小与重新连接均会影响结果，不把差值全部归因于并发调整。

该单轨道视频长 408 秒，下载约 57.8 MiB，平均媒体数据约需 145 KiB/s；若长期获取速度低于此值，连续播放会耗尽已缓冲数据。

## 对应用配置的含义

- 当前「备用 IP 直连」主要调整本站域名连接；本机 CONNECT 负责转发，远端出口仍是手机网络。它自身不提供远程加速线路。
- HLS 下载并发可选 1 至 32 路的预设值，默认 6；此设置影响离线下载分片，Media3 的在线播放仍由自身加载策略调度。
- 预加载时长能增加已下载数据的缓冲余量，实际获取数据的速率仍由网络和媒体服务决定。
- 后续若添加线路选择，应对实际视频域名做连接和持续吞吐测试，区分首页与媒体域名，并在手机上验证直连 / 指定代理；不要把切换首页域名或 DNS 直接标记为视频加速成功。
